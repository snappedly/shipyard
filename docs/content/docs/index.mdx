## What is Shipyard?

Shipyard is a TypeScript library and CLI for running AI coding agents in
sandboxes. Your script chooses an agent, a sandbox provider, a prompt, and a
branch strategy. Shipyard manages the sandbox lifecycle and collects the
agent's commits. The bundled templates provide issue workflows you can adapt.

## Quick start

You need Node.js 20.18.1 or newer and npm, Git, a running Docker engine, and
agent credentials.
For Codex, you can use either an OpenAI API key or a ChatGPT login.

### 1. Install

```sh
npm install --save-dev @snappedly-tools/shipyard
```

### 2. Initialize the target repository

```sh
npx shipyard init --template simple-loop --agent codex --codex-auth chatgpt --sandbox docker \
  --issue-tracker github-issues --build-image false
```

In an interactive terminal, `init` starts `codex login` if needed and asks that
login to use a one-time file-based credential store. Complete the browser login
and ensure `~/.codex/auth.json` exists; the generated entry point mounts it
read-only. Init creates `.shipyard/.env` from the generated example; fill in
any required credentials there. In a non-interactive environment, run
`codex login` before this command.
Leave `OPENAI_API_KEY` out of `.shipyard/.env` in this mode. To use API-key
authentication instead, use `--codex-auth api-key` and set the key in `.env`.
Set the scaffold's `GH_TOKEN` entry for GitHub Issues access. Review
`.shipyard/prompt.md` and adapt the issue workflow to your repository. Init
always attempts to create or update the lowercase
`shipyard` label; built-in issue workflows select only open issues carrying
that label.

### 3. Configure and run

Init generates `.shipyard/main.ts` for ESM projects (`"type": "module"`),
otherwise `.shipyard/main.mts`. That file configures the workflow; there is no
`config.json`.

Commit the setup files, leaving `.env` untracked. Label an issue `shipyard`
and `ready-for-agent`, then run the selected workflow:

```sh
npx shipyard run
```

The command detects `main.ts` or `main.mts`, finds the generated `Dockerfile`,
builds the cached image, and starts the workflow. The `simple-loop` template
implements eligible issues on separate branches and opens pull requests for
review. Use `npx shipyard run --skip-build` when the image definition has not
changed.

You can add `"shipyard": "shipyard run"` to the target project's scripts if
you prefer `npm run shipyard`. Shipyard's own repository script runs its
advanced multi-agent workflow instead.

## Next steps

- [Configuration](/docs/configuration): prompts, branches, hooks, and environment variables.
- [Agent providers](/docs/agents): choose an agent and configure authentication.
- [Repository runner](/docs/repository-runner): wake a foreground Shipyard
  controller from labelled GitHub Issues.
- Review the `simple-loop`, `sequential-reviewer`, `parallel-planner`, and
  `parallel-planner-with-review` templates before running them.

The optional workflow coordinator APIs support more elaborate hosted automation.
They are not required to run the library or its templates; ordinary use needs
no database, webhook service, or release-policy configuration.
